Exploring the Apple Fitness Dataset

1. About the dataset

This dataset contains 6,264 observations collected from an Apple Watch and Fitbit-like device.
Each row represents one time slice of recorded physical activity and biometric signals.

The variables describe:

  • demographic attributes (age, gender, height, weight)
  • physical activity metrics (steps, distance, calories)
  • heart-related measurements (hear_rate, resting_heart, entropy_heart, etc.)
  • computed features useful for modelling (corr_heart_steps, steps_times_distance)
  • the recorded activity class (activity), e.g. "Lying", "Sitting", "Walking", "Running"…

The dataset is ideal for demonstrating linear regression, feature engineering,
and exploratory visualisation because its variables are intuitive and quantitatively meaningful.

Packages for regression in this chapter

In this chapter we will work with a small, focused toolbox for regression models in R.

  • Base stats (lm() function) Simple linear and multiple regression using base R. We use it as the core engine: lm(hear_rate ~ steps, data = apple) is our starting point for modelling.

  • broom Tidies model output into tibbles.

    • tidy() – coefficients in a neat table,
    • augment() – fitted values and residuals attached to the original data,
    • glance() – one-row summary (R², AIC, …). This makes regression results easy to combine with dplyr and ggplot2.

  • Optional: modelr Helper functions like add_predictions() and add_residuals(). We will mostly rely on broom, but you may encounter modelr in other tutorials.

  • Optional: tidymodels A modern modelling framework with a unified grammar for regression, classification, resampling, and tuning. We briefly show how linear_reg() with engine "lm" reproduces the basic lm() workflow, and how the same interface extends to more complex models.

  • Optional: diagnostics packages (performance, car) For this R-focused course we keep diagnostics simple (plots and a few summary numbers). For deeper regression diagnostics (multicollinearity, detailed ANOVA, assumption checks), packages like performance or car are good next steps, especially in a statistics-oriented course.

6. First simple model: calories ~ steps

A natural first question:

How strongly are burned calories related to the number of steps?

We start with a simple linear regression:

model_simple <- lm(calories ~ steps, data = apple)
model_simple

Call:
lm(formula = calories ~ steps, data = apple)

Coefficients:
(Intercept)        steps  
   22.84232     -0.03076

The printed output shows the intercept and slope, but is not very tidy. We can use broom::tidy() instead:

tidy(model_simple)
# A tibble: 2 × 5
  term        estimate std.error statistic  p.value
  <chr>          <dbl>     <dbl>     <dbl>    <dbl>
1 (Intercept)  22.8      0.372        61.4 0       
2 steps        -0.0308   0.00150     -20.5 1.37e-90
  • the intercept is the expected calories when steps = 0,
  • the slope tells us how many calories increase on average when we add one step.

(Because steps can be large, it may be more interpretable to rescale them, for example to thousands of steps, later in the chapter.)

6.1 Visualising the simple regression line

apple %>%
  ggplot(aes(x = steps, y = calories)) +
  geom_point(alpha = 0.3, color = "#619CFF") +
  geom_smooth(method = "lm", se = TRUE, color = "#F8766D") +
  labs(
    title = "Simple linear regression: calories ~ steps",
    x = "Steps",
    y = "Calories"
  ) +
  theme_minimal(base_size = 14)

The regression line shows the average trend; the scatter of points around the line represents unexplained variability.

8. Basic diagnostics for the simple model

8.1 Residuals vs fitted values

apple_aug %>%
  ggplot(aes(x = .fitted, y = .resid)) +
  geom_hline(yintercept = 0, color = "grey50") +
  geom_point(alpha = 0.3, color = "#619CFF") +
  labs(
    title = "Residuals vs fitted values",
    x = "Fitted calories",
    y = "Residuals"
  ) +
  theme_minimal(base_size = 14)

We would like to see: * roughly constant spread of residuals across the range of fitted values, * no strong curvature.

8.2 Histogram and Q–Q plot of residuals

# Histogram
apple_aug %>%
  ggplot(aes(x = .resid)) +
  geom_histogram(bins = 40, fill = "#619CFF", color = "white") +
  labs(
    title = "Distribution of residuals",
    x = "Residual",
    y = "Count"
  ) +
  theme_minimal(base_size = 14)
# Q-Q plot
apple_aug %>%
  ggplot(aes(sample = .resid)) +
  stat_qq(color = "#619CFF") +
  stat_qq_line(color = "#F8766D") +
  labs(
    title = "Q-Q plot of residuals",
    x = "Theoretical quantiles",
    y = "Sample quantiles"
  ) +
  theme_minimal(base_size = 14)

These plots help us visually assess the normality assumption of residuals.

Note

Interpretation reminder

For this course we keep diagnostics informal and visual. In a full statistics course, you would add formal tests (normality, homoscedasticity) and check for influential points.

9. Multiple regression: adding distance and heart rate

Steps are not the only driver of calories. We can add more predictors:

model_multi <- lm(calories ~ steps + distance + hear_rate, data = apple)

tidy(model_multi)
# A tibble: 4 × 5
  term        estimate std.error statistic   p.value
  <chr>          <dbl>     <dbl>     <dbl>     <dbl>
1 (Intercept)  27.9      1.04        27.0  1.34e-151
2 steps        -0.0264   0.00147    -17.9  5.17e- 70
3 distance      0.136    0.00707     19.3  1.12e- 80
4 hear_rate    -0.0866   0.0114      -7.57 4.28e- 14

The interpretation now becomes: * each coefficient is a partial effect, * for example, the slope for steps describes the effect of steps when distance and heart rate are held constant.

Compare overall fit:

glance(model_simple)[c(“r.squared”, “adj.r.squared”)] glance(model_multi)[c(“r.squared”, “adj.r.squared”)]

Check your understanding * Did the multiple regression improve \(R^2\) markedly? * Are all predictors statistically significant? * Would you keep all of them in a parsimonious model?

Try to answer these questions before scrolling further or printing the summary in R.

10. Visualising model predictions

To keep the plot in two dimensions, we can fix some variables and vary only one of them. For example, fix hear_rate at its median and see how predicted calories grow with steps.

hear_median <- median(apple$hear_rate, na.rm = TRUE)

pred_grid <- tibble(
  steps     = seq(min(apple$steps), max(apple$steps), length.out = 100),
  distance  = median(apple$distance, na.rm = TRUE),
  hear_rate = hear_median
)

pred_grid <- pred_grid %>%
  mutate(calories_pred = predict(model_multi, newdata = pred_grid))

ggplot() +
  geom_point(
    data = apple,
    aes(x = steps, y = calories),
    alpha = 0.2,
    color = "#B3CDE3"
  ) +
  geom_line(
    data = pred_grid,
    aes(x = steps, y = calories_pred),
    color = "#F8766D",
    linewidth = 1.2
  ) +
  labs(
    title = "Predicted calories as a function of steps",
    subtitle = "Distance and heart rate fixed at their medians",
    x = "Steps",
    y = "Calories"
  ) +
  theme_minimal(base_size = 14)

This connects the algebraic model to a visual, more intuitive understanding.

11. Optional: interaction term

You might suspect that the effect of steps is different for low vs high heart rate. This can be expressed by an interaction:

model_interaction <- lm(calories ~ steps * hear_rate + distance, data = apple) tidy(model_interaction)

The term steps:hear_rate captures how the slope of steps changes with heart rate.

Tip

When to use interactions?

Use interaction terms when: * you expect the effect of one predictor to depend on the level of another predictor, * and you can explain such dependence substantively (not only because a p-value is small).

11. Optional: the same model via tidymodels

This course focuses on lm(), but it is useful to see that the same idea fits into the tidymodels ecosystem.

lm_spec <- linear_reg() %>%
  set_engine("lm")

lm_fit <- lm_spec %>%
  fit(calories ~ steps + distance + hear_rate, data = apple)
